CLI Overview ​

The @modelscript/cli package provides two identical binary executables: modelscript and its shorthand alias msx. The command-line interface serves as the primary headless automation driver for compiling, simulating, verifying, linting, rendering, and orchestrating polyglot engineering systems across local workspaces, CI/CD pipelines, and cloud HPC clusters.

Installation ​

You can run the CLI directly from the monorepo workspace using npx, or install it globally for system-wide access:

bash
# Run directly via npx
npx msx --help

# Install globally
npm install -g @modelscript/cli
msx --version

Global Options & Environment Variables ​

The CLI parser (apps/cli/src/main.ts) intercepts global execution flags prior to command dispatch and respects standard environment variables for headless CI/CD and enterprise hub integration:

Global Flags ​

FlagTypeDescription
--daemonbooleanRoute command execution through the persistent background compiler daemon (~/.modelscript/daemon.sock) to bypass cold-start WASM initialization and reuse warm Salsa caches.
--helpbooleanDisplay usage information and command-specific options.
--versionbooleanPrint the installed @modelscript/cli semantic version.

Environment Variables ​

VariableDefaultDescription
NO_COLORUnsetWhen set to any non-empty value, disables ANSI color sequences in terminal diagnostics, tables, and diff output.
MODELSCRIPT_API_URLhttp://localhost:3000Base URL for the ModelScript Hub, Package Registry, and Cloud HPC dispatch API (~/.modelscriptrc fallback).
MODELSCRIPT_TOKENUnsetBearer token (JWT or ms_bot_* service token) used for non-interactive authentication against the Registry, Cloud HPC, and Hub APIs (also accepts MODELSCRIPT_API_TOKEN).

Persistent Compiler Daemon (--daemon) ​

Standard CLI invocations spin up an isolated Node.js process, compile or load .wasm parser binaries, and index workspace dependencies from disk. When iterating rapidly or running hundreds of checks in a pre-commit hook, pass --daemon to any command:

bash
# Start or auto-spawn the background daemon and run lint with warm Salsa caches
msx lint model.mo --daemon

# Explicitly manage the daemon lifecycle
msx daemon status
msx daemon restart
msx daemon stop

When --daemon is passed, msx connects to the local Unix domain socket (~/.modelscript/daemon.sock on Linux/macOS or named pipe \\.\pipe\modelscript-daemon on Windows). If no daemon is running, the CLI automatically spawns one in the background, waits for readiness, and streams the command's stdout, stderr, and exit code back to the terminal.

Complete Command Reference by Category ​

The msx CLI registers 41 commands (plus ergonomic aliases) organized into six functional domains. See CLI Commands for exhaustive flag tables and examples for every command.

1. Compilation, Simulation & Optimization ​

CommandAliasesSummary
compileflattenFlatten a Modelica class hierarchy into a canonical Differential-Algebraic Equation (DAE) system.
instantiate—Instantiate a Modelica class and print its resolved component and equation structure.
simulate—Execute numerical DAE/ODE time-domain or steady-state simulations (JS, Arena, WASM, C, JIT, WebGPU, or Cloud HPC).
optimize—Solve nonlinear Dynamic Optimization and Optimal Control Problems (OCP) via direct collocation.
grad—Compute forward/adjoint parameter sensitivities ($\partial J / \partial p$) and finite-difference gradients.
surrogate—Run Design of Experiments (DoE), train Neural/Polynomial/RBF surrogates, and export ONNX/C/Modelica ROMs.
mc—Execute multi-threaded Monte Carlo uncertainty quantification and reliability sweeps.
csg—Extract Constructive Solid Geometry (CSG) primitives from Modelica models into 3D CAD meshes.

2. Linting, Formatting, Diffing & Localization ​

CommandAliasesSummary
lint—Run static syntax, type, structural, and control-flow diagnostics across polyglot workspace files.
parse—Parse source files with the native WebAssembly GLR parser and inspect the concrete syntax tree (CST).
format—Format source files canonically using CST-preserving pretty-printing.
unparse—Round-trip a parsed CST back into source text to verify lossless grammar unparsing.
diff—Compute structural AST/CST and semantic DAE diffs between two files or Git revisions.
pr-diff—Generate visual SVG/HTML architectural diffs and Markdown PR review comments against a base Git ref.
i18n—Extract translatable strings, compile locale catalogs, and translate model identifiers across languages.

3. Formal Verification, Safety & Test Synthesis ​

CommandAliasesSummary

verify-decisions—Verify architectural decision records (ADRs) and parameter trade-space bounds against formal system models.
decompose—Perform assume-guarantee contract decomposition and structural subsystem partitioning.
generate-tests—Synthesize MC/DC-complete unit test vectors and stimulus harnesses from formal model constraints.

Return Codes & CI/CD Integration ​

All msx commands return POSIX-compliant exit codes suitable for gating GitHub Actions, GitLab CI, or Jenkins pipelines:

Exit CodeMeaning
0Command succeeded with zero errors (or all verification obligations proved SAFE).
1Compilation error, static lint error (severity: "error"), counterexample falsification found, or runtime failure.
2Invalid CLI arguments, missing required flags, or unreadable input paths.

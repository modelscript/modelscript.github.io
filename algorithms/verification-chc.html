ModelScript Rationale & Modifications ​

Constrained Horn Clauses (CHCs) represent systems of logical relations of the form:

∀X.ϕ(X)∧P1(X)∧⋯∧Pk(X)⟹H(X)

Spacer solves CHCs by combining inductive generalization, Craig interpolation, and under-approximated reachability trees without bounding the unrolling depth. In ModelScript, Spacer verifies infinite-state state machine transitions and recursive cyber-physical control architectures.

  • Modifications: Directly integrates with ModelScript's in-WASM CDCL SAT core and Craig interpolator; implements specialized heuristics for linear real arithmetic over cyber-physical invariants.

2. IC3 / Property Directed Reachability (PDR) ​

Academic Citations ​

  • Bradley, A. R. (2011). "SAT-based model checking without unrolling."
    VMCAI 2011, LNCS 6538, pp. 70–87.
    DOI: 10.1007/978-3-642-18275-4_7
  • Een, N., Mishchenko, A., & Brayton, R. (2011). "Efficient implementation of property directed reachability."
    Formal Methods in Computer-Aided Design (FMCAD 2011), pp. 125–134.

ModelScript Rationale & Modifications ​

Proves whether safety property P holds across all reachable states of a discrete or hybrid transition system without unrolling the transition relation T(s,s′) to a fixed horizon k.

  • Modifications: Maintains inductive clause frames F0,F1,…,Fk where Fi over-approximates states reachable in up to i steps; uses counterexample-guided abstraction refinement (CEGAR) to block Proof Obligations (POBs); propagates clauses forward to find an inductive invariant (Fi≡Fi+1) proving unbounded safety.

ModelScript Rationale & Modifications ​

For continuous-time stochastic differential equations (Itô diffusions) driven by standard Wiener processes Wt:

dx(t)=f(x)dt+σ(x)dWt

deterministic trajectories do not exist, and safety verification requires bounding the tail probability that x(t) ever enters an unsafe region Xu={x∣∥x∥2≥ru}.

StochasticBarrierSynthesizer (packages/runtime/src/analysis/wasm_stochastic_barrier.ts) synthesizes non-negative supermartingale barrier candidates B(x)=xTPx≥0 using the infinitesimal generator L of the Itô process:

LB(x)=∇B(x)⋅f(x)+12tr(σ(x)σ(x)T∇2B(x))≤−c
  • Doob's Maximal Supermartingale Inequality: Bounds the infinite-horizon and finite-horizon probability of unsafe set entry via:P(supt≥0∥x(t)∥2≥ru)≤B(x0)+tr(ΣP)2αλmin(P)ru2≤δriskwhere Σ=σ(0)σ(0)T is the diffusion noise covariance and α is the linearized drift decay rate.
  • Soundness & Rigor Reporting: Emits structured VerificationVerdict diagnostics distinguishing fast linearized quadratic risk estimates from Sum-of-Squares (SOS) / LP certified supermartingales.

4. WebGPU Datalog / OWL 2 RL Saturation Reasoner (webgpu_reasoner.ts) ​

ModelScript Rationale & Modifications ​

Large-scale systems engineering ontologies (languages/owl2/ and SysML v2 KerML specialization hierarchies) contain 105 to 107 ABox/TBox assertions. Evaluating transitive role closures (subClassOf, partOf, satisfies) and SHACL numeric property constraints sequentially on the CPU becomes a bottleneck during workspace-wide verification.

WebGPUOntologyReasoner (packages/runtime/src/gpu/webgpu_reasoner.ts) implements a massively parallel GPU relational join and saturation co-processor with a CPU SIMD bitset fallback:

  • Bit-Packed Adjacency Matrix (BitsetGraph): Encodes an N×N directed graph as a flat Uint32Array where each node row u occupies ⌈N/32⌉ 32-bit words, achieving 32× memory compression and single-instruction bitwise row unions.
  • Parallel Logarithmic Doubling in WGSL (TRANSITIVE_CLOSURE_WGSL): Dispatches compute workgroups (workgroups = ceil(N / 64)) over ping-pong storage buffers (bufIn, bufOut) for ⌈log2⁡N⌉+1 doubling rounds, computing the full reflexive-transitive closure R∗ in O(log⁡N) GPU passes.
  • Parallel SHACL Constraint Kernel (SHACL_VALIDATION_WGSL): Validates SHACLNumericConstraint bounds (minInclusive, maxInclusive, expectedClassId) across strided Float32Array instance attribute tables and writes compact violation bitsets.

5. ISO 26262 / DO-178C Back-to-Back Equivalence Verification (b2b_verifier.ts, v_cycle_verifier.ts) ​

Academic Citations ​

  • ISO 26262-6:2018 & ISO 26262-8:2018. Road vehicles — Functional safety — Part 6: Product development at the software level (Table 7: Back-to-back comparison test between model and code) & Part 8: Supporting processes (Clause 11: Confidence in the use of software tools, TCL1).
  • RTCA DO-178C /DO-331 (2011). Software Considerations in Airborne Systems and Equipment Certification — Model-Based Development and Verification Supplement.

ModelScript Rationale & Modifications ​

Safety-critical automotive (ISO 26262 ASIL-D) and avionics (DO-178C DAL-A) standards require proving that generated embedded production code (zero-allocation C99 or standalone WASM FMU artifacts) is numerically and behaviorally equivalent to the high-level specification model (SysML v2 / Modelica).

B2BEquivalenceVerifier (packages/runtime/src/simulation/b2b_verifier.ts, orchestrated by UnifiedVerifier in packages/runtime/src/simulation/unified_verifier.ts) automates end-to-end Model-in-the-Loop (MiL) vs. Software-in-the-Loop (SiL) back-to-back verification:

  1. MiL Reference Trajectory Execution: Simulates the high-level DAE arena (simulateArenaAsync) over [tstart,tstop] to obtain reference trajectories yjMiL(t).
  2. Standalone C99 Code Generation & Cryptographic Hashing: Invokes generateStandaloneCSources (@modelscript/exchange/fmu) to emit self-contained, zero-allocation C99 sources (<Model>_standalone.h, <Model>_standalone.c), computing a SHA-256 artifact digest (cSourceHash) for V-cycle traceability.
  3. Automated Test Harness & Native Compilation: Synthesizes a deterministic C99 fixed-step RK4 test harness (<Model>_b2b_harness.c), compiles the binary via gcc -O2 -Wall -Wextra -std=c99 -lm, and streams CSV output trajectories yjSiL(tk).
  4. Bisimulation & Signal-Tolerance Equivalence Checking: Aligns SiL samples against binary-searched linearly interpolated MiL trajectories and verifies the combined absolute/relative tolerance envelope across all K time steps and M output signals:∀j∈{1,…,M},∀k∈{1,…,K}:|yjMiL(tk)−yjSiL(tk)|≤ϵabs+ϵrel|yjMiL(tk)|

Upstream & Downstream Pipeline Connections ​

  • Upstream Inputs:
    • State machine models and safety requirements from SysML v2.
    • Mode switching, discrete when / if clauses, and continuous/stochastic DAE arenas lowered from Modelica.
    • OWL 2 TBox/ABox ontological triples from OWL2.
  • Downstream Consumers:
    • Verifies architectural safety contracts, stochastic risk bounds, and ISO 26262 MiL/SiL equivalence in msx verify.
    • Feeds theory lemmas and transitive subsumption closures into Nelson-Oppen Coordinator.
